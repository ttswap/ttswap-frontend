# 全站优化方案与实施记录

## A. 当前页面评分（优化前）

以下为两份独立源码审查与浏览器检查的启发式评价，不是用户测试结果。

| 页面 | 评分 | 核心任务 |
|---|---:|---|
| 首页 | 6.5/10 | 理解协议并进入交易或市场 |
| 资产列表 | 6.5/10 | 查找、比较资产并进入交易或投资 |
| 资产详情 | 6/10 | 确认资产身份与指标，再决定交易或投资 |
| 个人中心 | 4.5/10 | 查看并管理自己的持仓、收益和记录 |
| 公售 | 4/10 | 理解当前阶段、支付金额与预计 TTS，再确认购买 |
| 资产管理 | 3.5/10 | 在当前网络找到管理的资产并配置参数 |

## B. 最大的 5 个问题

| 严重度 | 问题 | 原因及用户影响 | 具体处理 |
|---|---|---|---|
| Critical | 公售把全网记录标成我的记录 | 数据归属错误，用户可能误认为他人的成交属于自己 | 分开全网/个人记录，个人按钱包大小写无关筛选；未连接先给连接入口 |
| High | 资产管理手机没有配置入口 | 唯一表格隐藏在小屏，核心任务无法完成 | 复用资产列表的手机卡片与配置按钮 |
| High | 请求错误、未连接与无数据混淆 | 假零或空白让用户无法判断结果与恢复 | 统一连接、加载、空、错误状态，错误可重试，切链和账户忽略旧响应 |
| High | 公售前置条件不完整，提交被标成功 | 未连接仍提交，浏览阶段影响预估但不影响合约；广播并不等于确认 | 只用当前开放阶段预估，连接/切网门控，签前预览，等待成功回执 |
| Medium | 手机账户整页内容放在额外弹窗，详情参数过多 | 增加一步且叠加操作弹窗，信息层级失衡 | 账户使用页内标签；历史、所有者、费率及分佣参数默认折叠 |

## C. 优化优先级

1. 数据归属、提交状态、配置加载门控及移动核心入口。
2. 统一加载/错误/连接状态、旧请求隔离、键盘操作。
3. 信息层级、手机布局、按钮与数字样式。

## D. 推荐页面结构

Header：品牌主页链接 → 当前页导航 → 资产搜索 → 网络 → 语言 → 钱包；手机使用独立菜单按钮。

Home：协议说明与交易入口 → 真实协议指标 → 保留的产品说明 → 市场概览 → 交易统计。
Tokens：标题 → 已加载资产筛选/排序 → 桌面表格或手机卡片 → 快捷交换/投资 → 明确加载更多。
Token Detail：返回资产列表 → 资产身份/合约 → 价格、涨跌、每份净值、收益率 → 图表+交易（手机交易优先）→ 当前状态 → 折叠协议参数/历史统计 → 成交记录。
Profile：钱包连接或账号身份 → 两个主统计 → 可展开其余统计 → 页内持仓/资产/佣金/记录/邀请 → 短操作弹窗。
Sale：标题与网络 → 当前阶段购买卡/预计收到 → 阶段概览与可展开说明 → 全网/我的记录 → 签名前预览。
Asset Management：任务标题与说明 → 钱包连接或可筛选列表 → 配置弹窗；配置未读取成功前禁止提交。
Footer：文档、GitHub、X、Discord、邮件、Telegram。

## E. UI/UX 修改清单

- 保留资产、交换、投资、撤资、佣金、邀请、创建/更新/配置资产、公售功能与路径。
- 合并桌面和手机的账户导航；删除额外全页 Sheet，不删除账户栏目。
- 弱化公售在账户页的位置；资产管理成为独立辅助入口。
- 折叠详情的历史和管理参数、账户次要统计；不删除参数。
- 搜索同时支持全局资产搜索与明确标注的本地列表筛选。
- 修复行键盘事件劫持子按钮；实际验证 Enter 开启快捷交易。
- 移除 hover 抬升、过重阴影、多种强调色；交易为主按钮、投资为次按钮。
- 修复首页 GraphQL 字段 tokendecimals1 与实际 tokendecimals 不一致，恢复行情展示。
- 配置使用 BigInt 位运算，避免先浮点组合高位再转整数。

## G. Desktop 布局

≥1280px：单行导航，市场表格，详情/公售主体+440px操作区。768–1279px收窄间距，较窄平板用独立导航菜单，操作区380–400px；可横向滚动的表格保持列关联。

## H. Mobile 布局

<768px：单列16px边距；资产改卡片；账户标签页内横向滚动；详情交易先于图表；公售购买卡优先；弹窗在可视高度内滚动；地址缩略并可复制；长数字允许换行且不突破页面。390px所有六页验证 scrollWidth 等于 viewport。

## I. 交互状态设计

连接→钱包/网络检查→输入验证→预览→可能的授权→签名/提交→待确认→成功/失败。RPC确认不可用时公售提示结果未知并给交易链接，禁止立即重复提交。配置读取 loading/error/ready 独立于提交；error 禁止提交。资料表格初始加载不呈现空记录，请求失败有重试；分页显式按钮保证页脚可到达。

## J. 最终优化效果说明

核心操作更集中，手机减少整页弹窗步骤，次要协议信息按需展开，指标/余额/记录的身份与状态更明确。视觉统一于交易页深薄荷绿与浅色规范。

自查：保留完成任务必需的字段、真实数据、费用/风险提示和功能入口；删除多余容器、重复导航层、无意义动效。未为了装饰新增产品功能。

验证：交易与公售12项单元测试通过；生产构建通过；修改文件 Hooks规则检查通过；全项目类型检查仍有3项原有 Ondo模块缺失。六页桌面1280与手机390实页验证，无横向页面溢出。未连接真实钱包，未执行任何链上交易；连接后的账户、管理权限、实际授权签名需钱包验收。公售阶段来自当前索引累计金额与原有静态价格，最终结果以合约为准；没有新增收益或安全承诺。
